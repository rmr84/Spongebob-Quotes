# Bikini Bottom Daily

A daily "who said it?" guessing game built with Next.js, React and TypeScript. Each day you get one famous line from the
classic seasons and six guesses to name the character who said it.

- **140 famous quotes from seasons 1–5**, each checked word for word against the episode transcript, with the real speaker,
  episode and season
- **Wordle-style feedback:** every guess is compared with the answer on species, gender, home, job and debut season
  (🟩 match, 🟨 close, ⬛ miss, with ↑/↓ arrows for debut season)
- **Hints** unlock as you miss: the season after 2 wrong guesses, the episode after 3, the first initial after 4
- **Same puzzle for everyone**, changing at local midnight, with no repeats until every quote has been used
- **Optional accounts** (Google or email): progress saved across devices, plus Today, All-time and Best-streak leaderboards

## Run it

```bash
npm install
npm run dev        # http://localhost:3000
npm run build && npm start
```

Create a `.env` (it's gitignored) with:

```bash
MONGODB_URI="mongodb+srv://…"      # MongoDB Atlas connection string
# MONGODB_DB="bikini_bottom_daily"  # optional; this is the default
```

## How it's built

```
src/app/page.tsx            the game (client-side React)
src/app/api/…               API routes, which run on the server
src/components/             UI
src/lib/                    game logic shared by the browser and the server
src/server/                 MongoDB connection, sign-in verification, result validation
src/data/quotes.json        generated quote data
```

Player data is stored in **MongoDB**. The browser never connects to the database; only the API routes do. **Firebase** is
used only for signing in (and Analytics). The browser sends its Firebase ID token with each API request, and the server
checks it against Google's public signing keys (using `jose`). That check doesn't need a Firebase secret, only the project id.

| Route                         | What it does                                                         |
| ----------------------------- | -------------------------------------------------------------------- |
| `GET/POST/PATCH /api/me`      | Read, create (optionally importing this browser's stats), or rename your profile |
| `POST /api/results`           | Record a finished daily puzzle: `{ day, picks }`                     |
| `GET /api/results/:day`       | Your result for a day, used to restore the board on another device  |
| `POST /api/gauntlet`          | Record a finished Gauntlet run: `{ seed, rounds }`. The score is recomputed by replaying the run |
| `GET /api/leaderboard`        | `?board=today\|points\|streak\|gauntlet&day=N`. Public; includes your rank when you're signed in |
| `PUT/DELETE /api/me/avatar`  | Set your picture (a character, or an uploaded photo the browser shrinks to 256×256 first) or remove it |
| `GET /api/avatar/:uid`        | A player's uploaded picture (public, cached per version)              |

Collections in the `bikini_bottom_daily` database:

- `users`: `_id` is the Firebase uid, plus name and running totals
- `results`: one per player per day, `_id` is `uid:day`
- `avatars`: uploaded profile pictures, `_id` is the Firebase uid

Indexes are created automatically on first connection.

### Cheating

The server doesn't trust the browser's score. When a result comes in, the server replays the player's guesses against
that day's real answer, works out the outcome itself, and only accepts a puzzle from the last day or so, once per day.
Imported stats are checked to make sure they add up, and the score is recalculated on the server. A player can still find
the answer in the page's JavaScript before guessing; preventing that would mean the server hands out hints and checks
each guess one at a time.

**Points:** 6 for a first-guess win, down to 1 for a win on the last guess, and 0 for a loss.

## Deploying to Vercel

1. **Environment variables:** in the Vercel project, under Settings → Environment Variables, add `MONGODB_URI` (and
   `MONGODB_DB` if you want a different database name).
2. **Atlas network access:** Vercel functions don't have fixed IP addresses. In Atlas, go to Network Access and allow
   `0.0.0.0/0`, or use the Vercel ↔ MongoDB Atlas integration.
3. **Firebase sign-in:** in the [Firebase console](https://console.firebase.google.com/project/spongebob-quotes-fb8af), go
   to Authentication:
   - under **Sign-in method**, enable **Google** and **Email/Password**
   - under **Settings → Authorized domains**, add `spongebob-quotes.vercel.app`

## Quote data

`src/data/quotes.json` is generated by `scripts/fetch-quotes.mjs` from two lists of well-known lines:

- `scripts/iconic-quotes.json`, a hand-picked list
- the quoted section headings on the fan wiki's [List of memes](https://spongebob.fandom.com/wiki/List_of_memes) page

Every candidate is matched against the [SpongeBob fan wiki](https://spongebob.fandom.com) episode transcripts (CC BY-SA)
for seasons 1–5, so the game shows each line as it appears in the transcript, with its real speaker and episode.

```bash
npm run fetch-quotes                      # rebuild (downloads are cached in scripts/.cache)
npm run fetch-quotes -- --refresh         # re-download transcripts
npm run fetch-quotes -- --find "genius"   # search every transcript line, to check wording or speaker
```

To add a quote, add `{ "c": "patrick", "q": "the line as you remember it" }` to `iconic-quotes.json` and rerun the
script. If you're not sure who said it, leave out `"c"`. If you only want part of a long line, add `"show"` with the exact
excerpt. Adding quotes changes the order of upcoming daily puzzles; games already in progress aren't affected.

To choose the quote for a specific day, add it to `PINNED` in `src/lib/daily.ts` (puzzle number → exact quote text).
The pinned quote trades places with that day's quote, so nothing repeats.

## Local testing with the Auth emulator

```bash
firebase emulators:start --only auth      # needs Java
NEXT_PUBLIC_AUTH_EMULATOR=http://127.0.0.1:9099 FIREBASE_AUTH_EMULATOR_HOST=127.0.0.1:9099 \
  MONGODB_URI="mongodb://127.0.0.1:27017/?replicaSet=rs0" npm run dev
```

Point `MONGODB_URI` at a local or test database so test sign-ups don't end up in production.
